step21-gateway-source.txt - Kong's log stream as a live collector source (D-36)
Captured 4 September 2026 against the running Phase 1 + Phase 2 stack.
Author: Colile

The gap this closes: api-gateway was the one emitter in docs/soc-events.md
that the collector could never read live. Kong's default access log carries
no eventType, so soc/collector/reader.py skipped it as an application log
line, and UNAUTHORISED_ACCESS / RATE_LIMIT_EXCEEDED reached the rules only
through the hand-written --file capture.

=== 1. Kong's DEFAULT access log - why the reader skipped it ===========
nginx combined format: no eventType, no correlationId, no severity.
172.20.0.6 - - [04/Sep/2026:15:43:06 +0000] "GET /metrics HTTP/1.1" 200 22422 "-" "Prometheus/2.53.0"
172.20.0.6 - - [04/Sep/2026:15:43:24 +0000] "GET /metrics HTTP/1.1" 200 22422 "-" "Prometheus/2.53.0"

=== 3. Permitted traffic emits NO event ================================
A 200 through the gateway serializes to {} - no eventType, so the reader
skips it. The upstream service already logs REQUEST_RECEIVED for it, and a
gateway copy would double-count Rule 3's per-source volume signal.
Stub lines carrying eventId but no eventType: 0
